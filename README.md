# Слова — PWA-тренажёр интервального повторения

Статическое приложение без сборки и без обязательных библиотек. Русское слово → показать испанский ответ → «Не знаю», «Сомневаюсь», «Знаю». Тренировка продолжается без ограничения карточек, пока пользователь не остановит её. «Не знаю» возвращает слово в ту же сессию через пять других ответов или раньше, если очередь исчерпана. Слова берутся из Google Таблицы. Диакритика при оценке не сравнивается: пользователь оценивает ответ самостоятельно.

## Запуск на компьютере

```bash
cd ~/Downloads/spanish-recall-app
python3 -m http.server 8080
```

Открыть `http://localhost:8080`. Для первого знакомства можно нажать «Попробовать пример». Без Supabase прогресс хранится в браузере и доступны экспорт/импорт JSON.

## Формат Google Таблицы

Поддерживаются два формата: A=`Дубликаты` (испанский), B=`Перевод` (русский); либо столбцы `Русский` и `Испанский` (`RU`, `ES`). Для прочих двухколоночных таблиц используется A=испанский, B=русский. Если испанская ячейка содержит формы через `/`, берётся только основная форма до первого `/`. Необязательный `ID` — уникальный стабильный идентификатор слова. Например:

| ID | Русский | Испанский |
|---|---|---|
| word-001 | дом | casa |
| word-002 | сегодня | hoy |

Добавлять и менять слова можно прямо в Google Таблице. В приложении нажать «Обновить» на вкладке «Словарь». Для таблиц, доступных «Всем, у кого есть ссылка — Просмотр», приложение сначала пробует экспорт CSV. Успех зависит от политик браузера и доступа Google. Для закрытых таблиц необходимо настроить Google OAuth (см. ниже).

Когда столбца `ID` нет, приложение использует текст обоих переводов как идентификатор: при исправлении слова история по этой строке начнётся заново. С `ID` история останется.

## Многопользовательский запуск с Supabase

1. Создать отдельный проект Supabase; открыть SQL Editor и выполнить `schema.sql`.
2. В **Authentication → Providers → Email** разрешить вход по email и подтверждение ссылкой. Для тестового и рабочего адреса сайта добавить разрешённые Redirect URLs в **Authentication → URL Configuration**. Настроить SMTP для массовой отправки писем — встроенный сервис имеет ограничения.
3. Скопировать Project URL и **publishable / anon key** в `config.js` как `supabaseUrl` и `supabaseAnonKey`. **Service role / secret key использовать нельзя.**
4. Опубликовать папку на статическом HTTPS-хостинге, например GitHub Pages. У каждого пользователя свои записи в таблицах `profiles` и `reviews`, с RLS.

**Важно:** эта версия реализует простое адаптивное интервальное повторение (не FSRS). Логика: «Не знаю» — повтор сегодня и возврат в текущей сессии; «Сомневаюсь» — короткий интервал; «Знаю» — увеличенный интервал. Реальный FSRS можно заменить в `engine.mjs` после накопления истории; продукт пока не должен заявлять, что использует FSRS.

### Доступ к закрытым Google Таблицам

1. В Google Cloud Console включить **Google Sheets API**.
2. Настроить OAuth consent screen и создать **OAuth Client ID** типа Web application с разрешёнными JavaScript origins (адрес HTTPS-сайта или localhost).
3. Добавить Client ID в `config.js` как `googleOAuthClientId`.
4. Пользователь нажимает «Разрешить доступ Google» и соглашается на `spreadsheets.readonly`. Токен хранится **только в памяти вкладки**, не в Supabase.
5. Для закрытой таблицы указать название листа (если нужно) и нажать «Подключить / обновить».

В режиме публичной таблицы авторизация Google не запрашивается.

## Особенности первой версии

- Независимый прогресс по пользователям при настроенном Supabase, локальное сохранение без него.
- Доступен экспорт/импорт JSON, включая аварийную резервную копию.
- Неограниченная тренировка; если изучены все новые и просроченные слова, включается дополнительная практика без изменения интервалов.
- Встроенные демонстрационные слова не подменяют пользовательский словарь.
- Сейчас список слов кэшируется на каждом устройстве, а Supabase синхронизирует прогресс и адрес таблицы; для разных устройств словарь обновляется из Google Таблицы.
- Для промышленного публичного запуска стоит добавить централизованную телеметрию ошибок, миграции схемы, политику хранения данных и проверку на устройствах.
